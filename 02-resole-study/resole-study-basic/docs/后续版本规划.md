# 睿秀学城：版本拆解与评审规划

日期：2026-11-05；状态：首批范围按用户本轮纠正确认；后续版本为建议，未定排期、未创建副本。

用户本轮明确：首页完整保留；个人中心只保留个人资料及教学相关栏目，“我的学习/课程”及课程本身的教学功能完整带入。购买记录、积分成长不进入首批。此前已确认的 AI、在线编程评测、同步互动课堂继续后置。

## 1. 拆分原则

- 按业务能力是否必须一起完成拆分，不按页面数机械裁剪。首页的品牌与理念展示、个人资料与教学入口不因首批范围而改成简化占位页。
- 当前完整原型继续保留；只维护一份校内基础教学评审副本。后续各版先确认范围、依赖和验收，再决定是否创建相应副本。
- V1–V5 表示建议的能力阶段，后续阶段以已完成能力为基础，不是五套长期独立系统。评审副本 0.2 是文档/原型修订号，不是产品已上线版本。
- 首批要贯通真实账号、名册、课程、提交与成绩。界面恢复完整、能点击或保留本地记录，均不代表生产能力已经交付。

## 2. 版本总览

| 阶段 | 目标 | 主要范围 | 暂不包含 | 进入下一阶段前的验收重点 |
| --- | --- | --- | --- | --- |
| V1 校内基础教学 | 支撑一门课的日常教学，并保留完整基础使用体验 | 原首页全部内容/两种风格/合作机构入口；个人资料、头像、联系方式、密码与注销演示；我的学习、作业、考试、错题、教学收藏；课程总览/目录/作业测验/知识点/公告/讨论/团队/成果；手工备课、班级名册、入课审核、题库、批阅和成绩 | AI、执行评测、同步课堂、支付运营、积分成长、竞技 | 同一学生入课 → 学习 → 提交 → 教师批阅/发布 → 学生回看及教师统计；权限、附件、续答和结果一致 |
| V2 编程与实践训练 | 在已稳定的教学链中加入可执行的实践任务 | 编程/SQL 题库、题单、代码编辑、执行/评测、提交历史、错误反馈、课时配套题、教师查看提交 | 同步直播、AI 自动教学；竞技和相似度检测单独确认 | 题库发布 → 学生作答 → 安全执行 → 判分 → 成绩/进度回写 → 教师可查；先限定语言、SQL 范围及资源限制 |
| V3 互动课堂与教学反馈 | 支撑同一场课堂中的师生互动 | 课堂场次与人员、开始/结束、课件同步、签到/点名、小题/试卷发布、消息与禁言、课堂记录；真实音视频按场景另定 | AI 老师/同学；复杂预测模型 | 同一场次教师发起 → 学生收到/回应 → 教师记录更新；断线重连、结束清理与数据归档一致 |
| V4 开放运营与成长 | 按校外开放或收费运营目标扩展 | 专区/主题与内容运营、付费购买、订单/权益、退款/发票、个人购买记录、相关后台处理；积分/徽章/排行榜分专题确认 | AI 自动生成与个性化学习 | 支付 → 权益 → 学习入口 → 退款/票据状态一致；运营发布真正驱动前台；成长指标可解释、去重且有用途 |
| V5 AI 辅助教学与学习实验 | 在已有课程、题库和学习证据上验证 AI 的实际效果 | 先教师侧智能建课/生题/内容辅助，人工确认后采用；再学生知识点问答、引导学习、诊断和学习包；多角色课堂最后单独验证 | 无审核批量发布、未经证据自动授予正式成绩、一次铺满全部课程 | 先选一门课/一个知识点，验证内容质量、来源、教师复核、失败兜底、成本及学习效果，再决定扩展 |

V2 与 V3 的顺序可按首批试用学校需求调整，当前只确认它们不进入首批。V4 若无收费或开放运营目标，可推迟或不做；积分成长不作为开启交易的前置条件。V5 的原型研究可提前进行，正式接入及成果判定依赖基础课程、题库、权限与学习记录稳定。

## 4. 每轮评审应产出什么

1. V1：确认首批需求及正常/失败场景，补齐权限、发布、重交、考试恢复与成绩公开等规则；确定试用学校、样本课程和验收人。
2. V2：确认需要的语言/SQL、题型、时限、测试用例和人工复核范围，再评估执行服务；不先承诺支持任意代码或完整数据库能力。
3. V3：确认使用教室还是远程场景、同时在线人数与媒体需要，再评估同步和直播；播放区与互动区分别验收。
4. V4：先确认是否需要收费运营及售后政策，再定支付、票据、权益和后台流程；成长规则独立评审。
5. V5：先定义有价值且可验证的教学问题、采用范围和效果指标，再决定模型/内容服务与试点；不以生成速度替代教学质量。

不在本稿中给出未经估算的日期、工期或承诺。后续阶段只维护本规划，本轮不创建 V2–V5 Demo、分支、仓库或定时任务。
